# Evidence-gated structural v4 release

**Decision: ship the development-selected `structureVersion: 3` checkpoint**, not the rejected version-1 candidate. It passed the original release gate **without relaxing the 168/170 task-test floor**, and a new source-separated gate fixed before scoring the new rows. This is a same-size, single-model, offline browser/CLI change, **not a claim of deployment accuracy or authorship detection**. The formerly shipped correction-trained checkpoint is reconstructed by `correction_reference.mjs` from its pre-blend artifact, original 50% anchor and offline class head for all comparisons.

## Why this is different from the rejected trial

[The version-1 trial](STRUCTURAL_GENERALISATION.md) emitted abstract role pairs/triples for every sentence and misclassified an ordinary short task (“Take the last pastry”), dropping the historical test to 167/170. Version 2 restricted those patterns to a failure, code-shaped token or action-with-condition, but **failed development selection**: at 0.4 it improved Vitest issues 26/40→35/40 while decreasing Vitest commit subjects 32/46→31/46; other anchor fractions missed the unchanged development rule. No fresh set was scored for version 2.

Version 3 activates those learned role sequences when there is failure evidence, code shape, an action with a condition, **or at least seven tokens**. It still emits the specific failure/condition and code cues defined in `subsystems/richer_features.js`. Short, ordinary requests without these cues use the original v4 feature map. Unknown content words generally take the shared `TARGET` role rather than relying on a memorised project name. This gating was designed **after the version-1 mistake had been inspected**; the historical task test therefore cannot be described as a blind evaluation of version 3. There is still an English trigger vocabulary, a crude length heuristic, hashed collisions, and no true semantic or causal understanding. The threshold is unchanged. The feature bank remains **524,288 weights + one bias**; no runtime model switch or second classifier is added. Existing v4 checkpoints lacking `structureVersion` preserve their old scores; v1–v3 loaders and custom-corpus training remain supported.

Version 3 was fitted on the same 3,928 training rows (786 base train + 2,900 synthetic training-only + 131 prior real issues + 111 inspected correction titles), **none from the new test**. Selection used original-task and commit validation, authored ordinary-request checks and the already-inspected Vitest issue/commit partition, never the new set. The fixed development rule required no task-validation loss, near-preserved commit validation and ordinary requests, and gains in *both* Vitest contexts with bounded false negatives. `structure_v2_selection_trial.mjs 3` selected **0.4 anchor**: task 97/102 unchanged, commit validation 19/31 unchanged, authored ordinary 15/15 unchanged, Vitest issues **26/40→33/40** (FP 14→6, FN 0→1), commits **32/46→35/46** (FP 12→9, FN 2→2). The selected mix and metrics are preserved in `structure_v3_selection.json`.

## Release tests (all now inspected)

Before candidate fitting, `structure_fresh_locked.json` saved titles/subjects and one-rater labels from **Go issues page 8, Rails issues pages 12–13, Kubernetes issues page 25 and Bun commits page 10**. `structure_fresh_guard.mjs` verified source/label counts, URLs and no token-canonical overlap with previously saved training/diagnostic rows before scoring. Of **230** source rows, **179 informative, 9 vague and 42 unclear/duplicate/automated** were recorded; only **188 clear rows** were scored. Issue and commit rows are disjoint by source. Titles were selected by project and page, not randomly sampled, and a subject alone does not establish whether the code changed. Some labels (“Bump to 1.4.2,” a package name without version, and a vague issue with a component prefix) are subjective. This sample is extremely genuine-heavy and **does not measure deployed class prevalence or false-negative reliability**.

The saved new-set JSON has SHA-256 `306d044a11ae556ad8d9b2cc229a6d941ec57c4690669601d7c5544976ebe598`. The release rule was written in `structure_v3_release_trial.mjs` before the first prediction on those 188 rows. It retained the original first-trial gate: at least eight fewer issue FPs with at most two extra FNs; at least three fewer commit FPs and three more correct commits with at most two extra FNs; no original issue project worse by >2; historical task ≥168/170, unfamiliar ≥35/40, helpdesk-hard ≥12/16. It additionally required **≥3 more correct** new issues and commits separately, **≥12 fewer total FPs**, **≤2 extra FNs**, and no new project worse by >2. Both gates passed once on the frozen 0.4 candidate. Neither the labels nor the mix/threshold/cue lists were changed after opening the new set.

It supports a transfer hypothesis but is a descriptive split of the same already-opened set, not another test or a vocabulary-independence proof. The 47 residual false positives and two missed vague titles on the new set remain important. A single local run over 1,000 of these titles took ~369 ms for the old model versus ~500 ms for version 3; runtime varies by machine, but this is still local single-text scoring.

## Reproduce and limitations

`npm run train` fits version 3 for 120 epochs, uses the 0.4 prior and reattaches the licensed lexical head. It rebuilds `model.json` with **524,289 trainable scalars, 60,881 nonzero weights, 2,656,583 bytes**, 4,080 actual training-observed alphabetic words and 34,791 recognised alphabetic words including the offline lookup. The earlier 50%-anchored reference had 60,167 nonzero weights and 2,634,540 bytes. The frozen candidate assembled from a 0.5 checkpoint differs from the final deterministic CLI retrain by at most 2.3e-16 per coefficient due to floating-point mixing order; decisions and gate metrics agree. `experiments/task_structure_v3_unanchored_model.json` retains the pre-blend classifier for reproduction. The browser defaults to the identical feature version/anchor only for the intact default corpus; custom imports do not inherit task-specific structure or lookup. `npm run test:release` prints the class-wise project results and fails if either gate regresses; **rerunning it does not restore blindness**. `npm run test:model`, `npm run test:feedback`, and `npm run test:app` check model reconstruction, older formats, training-only feedback and real-server browser behaviour. The release gate, model, issue, lexical, real-text, feedback, context, domain, anchor, architecture, vocabulary and legacy suites passed; real-server browser smoke passed **42/42**, including a check that hidden repository files are not served. `git diff --check` passed.

This is a quality improvement for selected short project text, **not a general solution to real-world task suitability**. The locked set was source-separated but neither random nor multiply annotated, has only nine vague examples, and lacks issue bodies, true authorship or code-diff checks. The original gate was already inspected before version-3 design; the new gate was frozen before scoring but on a single-rater sample whose labels were known when the rule was written. The model still fails most non-English actionable authored probes and overflags 47 of 179 new informative titles. Independently annotated, temporally and author-separated, both-class evaluation is needed before using scores as automatic blocking decisions or asserting production accuracy.
